# Battle of Ages — робота з моделями

> Як ставити завдання на модель і як вона має виглядати на виході, щоб лягти в гру без переробок.
> Модель у коді (`MeshKit`, `SdfCreature`) — [SYSTEMS_GUIDE.md](SYSTEMS_GUIDE.md) §3, §5. Оновлено 2026-11-17.

## 0. Код чи Blender

- **За замовчуванням — код.** Пропи, будівлі, зброя, тварини й люди будуються в `Utils/*Builder` на `MeshKit` /
  `SdfCreature`: одна модель на всіх, далекий меш, колір і поверхня на вершині, без текстур. Так і лишається для всього,
  що складається з брусів, тіл обертання й ліплених форм.
- **Blender — коли форму важко описати кодом** (вигнуте лезо, складний механізм, різьблення) або коли є готова модель,
  яку треба почистити. Blender 5.3 стоїть (`C:\Program Files\Blender Foundation\Blender 5.3\blender.exe`), skills
  `blender-*` керують ним без вікна. Blender MCP не встановлено (див. §7).
- Що б не робили в Blender, у грі модель мусить стати тим самим, що будує код: **один меш, один матеріал, колір і
  поверхня на вершині** (§4). Без цього вона не зіллється з тілом персонажа й не намалюється пачкою в натовпі.

## 1. Як ставити завдання (що писати в промпті)

Добрий промпт на модель називає все, від чого залежить, чи її доведеться переробляти:

1. **Референс файлом у репозиторії** — `Art/references/<назва>.png` (і вкладенням у чат). Не «як у грі X», а картинка.
2. **Перелік моделей** — повний, щоб агент робив їх підряд в одному стилі й масштабі.
3. **Рухомі частини — окремими об'єктами** і навіщо вони рухатимуться (тятива, засув, ворота, кришка скрині, колесо,
   важіль). Потім саме їх крутить анімація чи код, а не всю модель (§3).
4. **Точки дії** — де щось з'являтиметься: вістря, звідки летить стріла, отвори для диму чи вогню, місце для руки, де
   кріпиться щит. Це порожні об'єкти-сокети (§3).
5. **Риси форми, без яких річ не впізнати** — «вигнуте лезо», «кільце на руків'ї», «три обручі на бочці».
6. **Реальні розміри в метрах**, форма, кольори й матеріали як на референсі.
7. **Бюджет** — легка модель, далекий меш (§5).
8. **Куди зберегти й у яких форматах** (§2).
9. **Межа завдання** — «лише моделі, у гру поки не вбудовуй» або навпаки «підключи в `GearMeshBuilder`».
10. **Без проміжних звітів, але з перевіркою** — наприкінці один аркуш знімків усіх моделей (§6), а не «готово» на слово.

Шаблон — у §8.

## 2. Папки й формати

| Що | Де | Чому |
|---|---|---|
| Референси | `Art/references/` | поза `Assets`: Unity не імпортує зайві картинки |
| Джерело `.blend` | `Art/Blender/<категорія>/<Назва>.blend` | поза `Assets`: `.blend` усередині змушує Unity запускати Blender при кожному імпорті |
| Для гри | `Assets/Models/<категорія>/<Назва>.fbx` | Unity читає FBX сам; пакета glTF у проєкті немає, тож `.glb` не годиться |

Категорії: `Weapons`, `Armor`, `Props`, `Buildings`, `Creatures`. Назва — латиницею, `PascalCase`, однакова в `.blend`,
`.fbx` і об'єкті-корені (`Kerambit.blend` → `Kerambit.fbx` → корінь `Kerambit`).

## 3. Будова моделі

- **Масштаб:** 1 одиниця = 1 метр, масштаб і поворот застосовані (Apply All Transforms), експорт пресетом Unity зі
  skill `blender-export-pipelines` (FBX, осі під Unity). Перевірка розміру — габарити в метрах у звіті експорту.
- **Початок координат (pivot):**
  - зброя й інструмент у руці — **центр хвату** (де стискається кулак), лезо / держак уздовж **+Z у Blender** (стане +Y
    у Unity: так будує `GearMeshBuilder.BuildWeapon`, «built along +Y»), ріжуча кромка / лице — до глядача (−Y у Blender);
  - щит — центр зворотного боку, де передпліччя;
  - пропи й будівлі — центр низу, на землі (Z = 0).
- **Рухомі частини** — окремі об'єкти-нащадки кореня, назва `<Модель>_<Частина>` (`Crossbow_String`, `Gate_LeftWing`),
  pivot кожної — на осі її руху (петля, вісь колеса, напрямна засуву). Нерухоме — одним об'єктом `<Модель>_Body`.
- **Сокети** — порожні об'єкти (Empty) `Socket_<Що>` (`Socket_Tip`, `Socket_Smoke_01`, `Socket_Hand`), вісь +Z — куди
  спрямована дія. FBX переносить їх як порожні `Transform` у Unity.
- **Без** кісток, якщо модель не гнеться; без модифікаторів у файлі для гри (застосувати перед експортом); без
  прихованих і службових об'єктів у FBX.

## 4. Матеріали: колір і поверхня на вершині

У грі **немає текстур** для моделей: шейдер `Custom/CharacterSurface` малює деталі процедурно з двох даних на вершині —
колір (vertex color, sRGB у Blender → лінійний у Unity) і поверхня `UV2 = (візерунок, metallic, smoothness)`.

- У Blender — **по матеріалу на тип поверхні**, назва з префіксом `S_`, колір — Base Color матеріалу (або атрибут кольору
  на вершині для переходів):

| Матеріал | Візерунок | Як у коді (pattern, metallic, smoothness) |
|---|---|---|
| `S_Skin` | 0 шкіра | — |
| `S_Cloth` | 1 тканина | (1, 0, 0.05) |
| `S_Leather` | 2 шкіра-матеріал | (2, 0, 0.36) |
| `S_Metal` | 3 метал | залізо (3, 0.8, 0.42), лезо (3, 0.7, 0.28), золото (3, 0.95, 0.72) |
| `S_Wood` | 4 волокна (дерево й волосся) | (4, 0, 0.22) |
| `S_Eyes` | 5 очі | — |
| `S_Fur` | 6 хутро | — |
| `S_Mail` | 7 кольчуга | (7, 0.85, 0.5) |
| `S_Stone` | 8 камінь / тиньк | (8, 0, 0.2) |

- Пласкі блискучі поверхні (лезо, вода) — матові (smoothness ≤ 0.3): сонце в них дає сліпучий відблиск із bloom.
- **Перетворювача ще немає.** Перша модель з Blender потребує інструмента в `Editor/` (робоча назва
  `BlenderMeshImport`): читає FBX, зливає частини в один меш на `MeshKit.PropMaterial()`, назву матеріалу `S_*` перекладає
  в колір + `UV2` за таблицею вище, будує далекий меш і зберігає `.asset` (як `Resources/Creatures` у
  `BakeCreatureMeshesTool`). Рухомі частини лишає окремими мешами-нащадками, сокети — порожніми `Transform`.

## 5. Бюджет

Тисячі людей на екрані: зброя й броня зливаються в меш кожного тіла (`GearMeshBuilder`), тож їхня вага множиться.

| Що | Близький меш | Далекий меш |
|---|---|---|
| Зброя, інструмент у руці | ≤ 400 трикутників | ≤ 80 |
| Щит, шолом, наплічник | ≤ 600 | ≤ 120 |
| Проп (бочка, скриня, верстат) | ≤ 2 000 | ≤ 300 |
| Будівля | ≤ 6 000 | ≤ 800 |

Орієнтир — моделі в коді (меч: тіло обертання на 8 сегментів; далекий лицар 3 581 вершина на все тіло зі зброєю).
Більше — лише з причиною й заміром (`StressTest` / `MassProbe` проти бази того самого дня). Один матеріал на модель,
жодних окремих об'єктів-рендерерів на дрібниці. Скорочення — skill `blender-game-optimization`.

## 6. Перевірка (обов'язково)

1. **У Blender** — skill `blender-asset-qa` перед експортом: нормалі, дірки, дублі, накладені грані (z-fighting),
   незастосований масштаб, відірвані шматки; аркуш знімків з кількох боків — кожну модель окремо й усі разом у масштабі.
2. **Після експорту** — відкрити FBX ще раз (повторний імпорт у Blender або звіт skill-а): габарити в метрах, кількість
   трикутників, назви частин і сокетів.
3. **У грі** (коли модель підключена): знімок — `GearCapture` (на персонажі), `ViewmodelCapture` (від першої особи),
   `ObjectCapture` (пропи, `CAPTURE_LIST`). Зміна `MeshKit`/`SdfCreature` → `SetupFpsViewmodelTool.ConfigureInSampleScene`.
4. Наприкінці — один звіт: таблиця «модель → трикутники близько/далеко → розмір у м → рухомі частини → сокети» і шлях до
   аркуша знімків.

## 7. Інструменти

- Blender 5.3 і 28 skills `blender-*` (`C:\Users\kfcrf\tools\blender-skills`, оновлення: `git pull` там і повторно
  `install\install.ps1 -Agent claude`). Головні для моделей: `blender-hardsurface-modeling` (зброя, механізми),
  `blender-asset-qa`, `blender-game-optimization`, `blender-export-pipelines`, `blender-workflow-recipes` (повний шлях
  пропа).
- Blender MCP (живий Blender у вікні) — за бажанням, ставить автор сам:
  `uvx mcp-for-blender install-addon`, потім `claude mcp add blender uvx mcp-for-blender`. Без нього все те саме
  робиться без вікна; MCP зручний, щоб дивитися, як модель росте.
- Не тягне ноутбук (RTX 4060, 8 ГБ): TRELLIS.2, HY-Motion. Локальна картинка → 3D, якщо знадобиться, — Modly
  (Hunyuan3D, ~6 ГБ); така модель однаково йде через ретопологію й §3–§6.
